# Такт

Chrome-расширение для учёта времени: WXT, Vue 3 Composition API, PrimeVue, TypeScript (strict), Manifest V3. Сервер и отдельная авторизация не нужны.

## Запуск и установка

Нужны Node.js 22+ и npm.

```sh
npm install
npm run dev
npm run test
npm run typecheck
npm run format
npm run format:check
npm run build
npm run zip
```

После `npm run build` откройте `chrome://extensions`, включите **Режим разработчика**, нажмите **Загрузить распакованное расширение** и выберите `.output/chrome-mv3`. Закрепите «Такт» на панели Chrome. Для разработки загрузите `.output/chrome-mv3-dev` после `npm run dev`. После обновления production-сборки нажмите «Обновить» на карточке расширения. Не удаляйте расширение при обновлении: удаление очищает его локальное хранилище.

Материалы и порядок публикации в Chrome Web Store описаны в [`store/README.md`](store/README.md). Политика конфиденциальности находится в [`PRIVACY.md`](PRIVACY.md) и доступна внутри расширения по ссылке внизу интерфейса.

Страница параметров открывается кнопкой в попапе или через карточку расширения. В попапе показана история за текущий месяц. На странице параметров сначала показан текущий месяц; стрелками можно перелистывать месяцы истории. Экспорт JSON/CSV охватывает всю историю, также доступен импорт JSON.

## Использование

- Введите название и нажмите Start. Кнопка + появляется у последнего запущенного таймера и добавляет строку для другого таймера. Пока новая строка открыта, кнопка скрыта и появляется снова после запуска следующего таймера. У единственного нового поля ввода кнопка × не отображается; при нескольких строках она скрывает новое поле. У активного таймера кнопка × отображается всегда и удаляет его без записи времени после подтверждения. Удаление можно отменить в течение 5 секунд. Stop завершает выбранный таймер с записью в историю.
- При нажатии Start расширение проверяет активную вкладку. Если открыта задача Jira, её ключ добавляется к названию, а ссылка сохраняется в записи. Если название таймера не введено, расширение берёт тему задачи из заголовка вкладки Jira, когда она там есть. Значок ↗ рядом с активным таймером и названием в истории открывает задачу. Ссылку можно изменить в форме редактирования; повторный запуск из истории переносит её в новый таймер.
- Таймеры продолжаются при закрытом попапе и браузере: длительность вычисляется из timestamps. Изменить начало, название и оплачиваемость можно через ✎ без остановки. Название также сохраняется после выхода из поля.
- ₽ обозначает **оплачиваемость**, а не факт получения оплаты. Кнопка переключает этот признак.
- Ручной ввод позволяет задать начало и окончание с отдельными датами либо длительность ЧЧ:ММ. Сохранение не затрагивает активные таймеры. При редактировании через длительность окончание пересчитывается.
- История группируется по локальной дате начала записи, неделя начинается в понедельник. Запись через полночь относится целиком к дню начала. Итоги суммируют параллельные записи.
- ▶ создаёт отдельный таймер с тем же названием и оплачиваемостью. Удаление требует подтверждения, после него «Отменить» доступно 5 секунд. Повторное удаление заменяет предложение отмены предыдущего.

## Хранение и синхронизация

Все записи и метки удаления находятся в `chrome.storage.local`, отдельно под ключами `record:<id>`. Фоновый service worker последовательно выполняет команды из всех открытых страниц.

В `chrome.storage.sync` дополнительно помещаются активные таймеры и до 100 последних завершённых записей. Расчёт учитывает размер каждого элемента, общий объём и количество ключей; при нехватке места окно завершённых записей уменьшается. Метки удаления имеют приоритет. История, исключённая из sync, остаётся локально. Если даже активные таймеры или метки удаления не помещаются, появляется сообщение об ограничении; локальная копия сохраняется.

Записи sync объединяются по уникальному ID и `updatedAt`; при равенстве timestamps метка удаления имеет приоритет, остальные конфликты разрешаются детерминированно. Удаление ключа из окна sync не трактуется как удаление записи. `storage.onChanged` обновляет страницы и объединяет изменения с других устройств. Для корректной хронологии изменений часы устройств должны быть настроены правильно. Очень большая история меток удаления может превышать ёмкость sync; метки сохраняются локально без ограничения срока.

Изменения записываются при действиях, а не при секундном обновлении счётчика. Попытки sync разделены минимум 10 секундами, время последней попытки хранится локально и переживает перезапуск worker. Изменения внутри этого интервала сохраняются сразу локально и отправляются отложенно через `chrome.alarms` (обычно спустя 30 секунд; Chrome может задерживать alarm). Одна попытка использует максимум два изменения sync (`remove` и `set`), что ниже квот 120 операций/мин и 1800/час. Ошибки отображаются, повторная отправка запланирована через минуту. Общие лимиты заложены с запасом: 100000 байт, 8000 на элемент, 500 ключей.

В истории синее облако с галочкой означает, что актуальная версия записи успешно сохранена в `storage.sync`, **не подтверждает доставку на другое устройство**. Серый контур облака обозначает локальную запись или изменение, ожидающее отправки. Смысл иконки доступен через подсказку и название для скринридера.

Работа без входа в Google полностью доступна. Для передачи между устройствами включите синхронизацию Chrome; расширение самостоятельно не авторизуется и не может гарантировать, что пользователь включил облачную синхронизацию. На устройствах должен совпадать ID расширения: для распакованных установок он зависит от пути/ключа. Для надёжной установки на разных устройствах используйте одно опубликованное расширение либо сборки с одинаковым публичным manifest `key`.

JSON содержит все записи, включая активные таймеры и метки удаления: `{ format: "takt", version: 1, records: [...] }`. Импорт проверяет весь файл до изменения хранилища и объединяет по ID; повторный импорт не создаёт дубли. Размер файла ограничен 20 МБ. CSV содержит завершённые неудалённые записи, timestamps в ISO UTC, длительность в секундах, UTF-8 BOM и экранирование для таблиц. Файлы обрабатываются только JavaScript; данные никуда не загружаются.

## Проверки

Модель записей, команды фонового процесса, интерфейс Chrome storage, формы и события Vue типизированы в `lib/types.ts`. Импорт и данные из хранилища проверяются во время выполнения; TypeScript не заменяет проверку внешнего JSON. Конфигурация WXT и entrypoints тоже написаны на TypeScript.

`npm test` запускает тесты TypeScript через Node.js и tsx с имитацией Chrome storage и alarms. Покрыты параллельные таймеры, восстановление после создания нового фонового обработчика, ручные записи, редактирование времени, метки удаления и отмена с 5-секундным сроком, JSON/CSV, конфликты, группировка недель, квоты размера/числа элементов/частоты и ошибки sync.

Ручная проверка после установки:

1. Запустите два таймера, закройте попап, снова откройте. Перезапустите Chrome и проверьте счётчики. Остановите один: второй продолжает идти.
2. Добавьте ручную запись при работающем таймере. Измените длительность завершённой записи, затем начало активного. Проверьте окончание, счётчик и суммы.
3. Переключите ₽, запустите ▶, удалите запись и отмените в течение 5 секунд. Затем удалите повторно и подождите: отмена должна исчезнуть.
4. Откройте параметры и попап одновременно: изменения отражаются в обеих страницах. Экспортируйте JSON/CSV, импортируйте JSON дважды: число записей не увеличивается. Некорректный JSON не изменяет историю.
5. Импортируйте >100 завершённых записей: старые остаются локальными. С длинными названиями окно sync уменьшается. Для проверки ошибки sync подставьте ошибку `QUOTA_BYTES` в мок теста; локальные данные должны сохраниться и ошибка должна исчезнуть после успешного повтора.
6. На двух Chrome с одним ID расширения и включённой синхронизацией проверьте новые записи и метки удаления. Доставка зависит от Chrome, её время расширение не определяет.

### Статус проверки в среде создания

Проходят 13 автоматических тестов, строгая проверка типов `npm run typecheck` (включая Vue-шаблоны и тесты), `npm run format:check` и production-сборка `npm run build`. Ручные проверки интерфейса в Chrome и доставка sync между реальными устройствами пока не подтверждены.
